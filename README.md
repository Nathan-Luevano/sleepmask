# sleepmask — x86-64 position-independent shellcode, studied across PE32+, ELF, and Mach-O

A small, self-contained research codebase on **position-independent x86-64
shellcode** and the behavior of the three dominant native executable formats —
PE32+ (Windows), ELF (Linux), Mach-O (macOS) — at the point where a binary is
still just bytes: headers, load commands, entry points, and the loader
structures each operating system hands the process.

The core questions driving the work:

1. **Construction.** How far can a zero-import payload go — no IAT, no CRT,
   no import table of any kind, every kernel entry a direct `syscall` — if it
   must resolve everything at runtime from the process's own loader state
   (the PEB and LDR on Windows, class-tagged syscalls on XNU, raw syscalls on
   Linux)? And what is the *minimal structurally valid* PE32+/ELF/Mach-O image
   that can carry such a blob?
2. **Validation.** How do you prove those images behave correctly when the
   kernel you are targeting is not the one under you? The answer used here:
   execute the Linux artifact for real, run the Windows/macOS images from
   their *real entry points* in Unicorn with only the kernel interface
   emulated, and cross-check every format with an independent stdlib-only
   reader that was written against the image, not the writer.
3. **Host coupling.** Given a host binary you do not want to recompile, what
   is the smallest structural change that redirects its entry point through a
   new, appended, position-independent code region — and how do you prove the
   host itself is unharmed? (A 10-byte trampoline, one new RWX section, zero
   modified host bytes.)

The techniques are format-agnostic in the places that matter and deliberately
per-format in the places that are not; the codebase is organized so that each
claim is reproducible with one command.

## The artifacts

| artifact | format | size | mechanism |
|---|---|---|---|
| `build/sleepmask.exe` | PE32+ x64, no imports | 2048 B | walks the PEB (`gs:[0x60]`) → `Ldr` → in-load-order list → `ntdll.dll`; parses the export directory; reads the syscall numbers for `NtDelayExecution`, `NtProtectVirtualMemory`, `KeQuerySystemTime` out of the export stub prologues (`B8 nn 00 00 00 0F 05`); marks the `NtDelayExecution` text RWX and overwrites it with a 12-byte mask that polls `KeQuerySystemTime` and restores the original bytes on return; re-protects, sets its done flag, and returns into the 9-byte entry trampoline (which idles in a `pause` loop with the mask live in-process) |
| `build/sleepmask_linux` | static ELF x86-64 (`gcc -static`) | ~785 KB (CRT + 81 B payload) | stage-0 loader: `mmap` a fresh RWX page, `memcpy` the 81-byte PIC payload in, jump to it. The payload emits `sleepmask: armed \| linux x86-64 \| self-injected` on fd 1 and `exit(0)`. **Executed for real; stdout byte-checked.** |
| `build/sleepmask_macho` | Mach-O `MH_EXECUTE` x86_64 | 4177 B | same 81-byte PIC payload with XNU class-tagged syscalls (`eax = 0x2000000 \| nr`; `write` = 0, `exit` = 1), in a two-load-command executable (`LC_SEGMENT_64` `__TEXT` + `LC_MAIN`) |

All blobs are **position-independent** — RIP-relative / `call [rel]`-resolved
addresses only — so they run at any base. The macOS test re-runs the image at
a `+0x1000` slide to prove the property rather than assert it.

## The three mechanisms, precisely

**Runtime resolution (the Windows blob).** No imports means the syscall
numbers and the function pointers must come from somewhere the process already
trusted: `gs:[0x60]` → PEB → `Ldr` (+0x18) → the in-load-order DLL list
(`Flink`-chain with the `+0x08` self-reference stop marker) → first entry's
`DllBase` (+0x60) → `e_lfanew` ([+0x3C]) → optional header → export directory.
The syscall number for each API is not a constant but a *measurement*: each
export stub is read and its prologue decoded (`mov eax, nr; syscall`), which
is what makes the blob immune to a kernel that renumbers its syscalls.

**Sleep masking.** With `NtDelayExecution`'s own bytes under the process's
control, "sleeping" becomes observable: the mask swaps the entry for
`mov rax, <stub>; jmp rax`, the stub polls `KeQuerySystemTime` for the
requested duration, restores the original twelve bytes, and returns. The
harness asserts the restored bytes are byte-identical to the captured
original (`b8 3d 00 00 00 0f 05 c3 00 00 00 00`).

**Host coupling (the appenders).** Each appender adds one new RWX section at
a fresh page `V` containing exactly:

```
E8 05 00 00 00      call +5   -> the appended blob (10 bytes further on)
E9 xx xx xx xx      jmp disp32 -> the ORIGINAL entry point
<the appended blob, byte-identical>
```

The `call` pushes `V+5` (the `jmp`) as its return address; the blob — a PIC
function that saves and restores all 15 general-purpose registers and
`ret`s — lands the flow on the `jmp`, and the host's original entry runs with
its registers intact. Entry re-pointing per format: PE
`AddressOfEntryPoint` → `V`; Mach-O `LC_MAIN` entryoff → `V`; ELF relocates
the program-header table and re-points `PT_PHDR` (the host's `PT_LOAD` layout
gains exactly one segment). The host's original bytes are never modified —
the appenders' output is diff-checked against the input for that.

## Validation model — native vs emulated, stated plainly

| layer | what is proven | how |
|---|---|---|
| **Linux artifact** | runs on a real kernel | built (`gcc -static`) and executed; stdout and exit code byte-checked |
| **Linux host coupling** | the grafted host behaves | coupled ELF executed on real metal, PIE and `-no-pie`; beacon line precedes host line byte-exactly, host exit status (42) preserved, `PT_LOAD` count +1 |
| **Windows artifact & coupling** | runs to the CPU boundary | full image loaded in Unicorn from its real entry point, with a hand-built PEB/ntdll and the kernel interface emulated at `syscall` (0F 05); asserted: syscall trace, done flag, byte-restore, beacon-before-host ordering, exit 42, GPR sentinels. The coupled image is run twice — with real and with decoy syscall numbers — proving the number is *read from the export prologue*, not assumed. **No native Windows execution yet.** |
| **macOS artifact & coupling** | runs to the CPU boundary | Unicorn with an XNU syscall-class emulator (`0x2000000 \| nr`), at the nominal base **and** slid `+0x1000`; independent generic load-command walker agrees with the static pass. **No native macOS execution yet.** |

What "no native Windows/macOS execution yet" means, concretely: the images
are structurally complete and execute correctly up to the kernel boundary
under emulation, with every loader contract (PEB offsets, LDR entry layout,
export-dir fields, stub prologue format, XNU class tags) taken from the
documented ABI and exercised by the harness — but the one run that would
close the loop on real hardware has not happened. That is the stated
limitation of the Windows/macOS layers, and the reason they are emulated
rather than asserted.

## The test matrix

```
bash build.sh            # nasm -g -f bin, every .asm in src/ -> build/*.bin
bash tests/test_all.sh   # the 8-layer matrix, one command
```

```
  PASS  build (nasm -f bin)
  PASS  linux (real ELF, executed)
  PASS  linux-coupled (append_elf, PIE + no-pie, on metal)
  PASS  windows (PE32+ + unicorn entry)
  PASS  windows-coupled (append_pe + unicorn, real + decoy nr)
  PASS  macos (Mach-O + unicorn xnu)
  PASS  macos-coupled (append_macho + unicorn, base + slide)
  PASS  harness (raw blob, PEB walk)
------------------------------------------------------------------
ALL 8 LAYERS GREEN
```

Layer notes:

- **windows / windows-coupled** — `tools/mk_pe.py` writes the PE32+; the test
  validates header fields, re-parses with the independent stdlib-only reader
  in `research/pe/`, then runs the *whole image* in Unicorn from the real
  entry point. Asserts the syscall trace (`0x2B 0x2B` — two
  `NtProtectVirtualMemory` calls), the done flag, the 26 `KeQuerySystemTime`
  polls, and byte-identical restore of `NtDelayExecution`.
- **macos** — `tools/mk_macho.py` writes the Mach-O; the test walks the load
  commands with an independent generic walker, then runs in Unicorn at the
  nominal base and again slid `+0x1000` (the PIC check).
- **harness** — the raw 1267-byte Windows blob against a hand-built fake
  PEB/ntdll: PEB walk → export parse → syscall-number extraction →
  `NtProtectVirtualMemory(RWX)` → mask install → byte restore.

`research/pe/` is exercised separately: `selftest.py` (18 checks, regenerates
its fixture) and `crosscheck.py` (the offline syscall table against the
runtime harness's observed trace).

## Requirements

- Linux x86-64 (developed on Ubuntu 24.04), `nasm`, `gcc`
- a Python 3.12 env with `capstone`, `keystone-engine`, `unicorn`
  (here: micromamba env `mdev`; run python as
  `micromamba run -n mdev python <script>`)

No lld/lld-link, wine, mingw, or macOS toolchain is required — which is
precisely why the PE32+/Mach-O writers and appenders are Python.

## Responsible use / research scope

- This is **research and test code**, not a product and not a security
  boundary. It runs with whatever privileges the process it is run (or grafted
  into) already has.
- The Windows and macOS layers are validated **under emulation up to the
  kernel boundary**, not on native hardware; the Linux layer is native.
  Nothing here should be read as a claim of production behavior on those
  platforms.
- The host-coupling appenders modify binaries. Run them on copies you can
  afford to change, and keep the inputs around — the appenders are designed
  to be diffed against them.
- Intended context is authorized lab use: your own test hosts, your own
  binaries, your own machine images.

## Status

- Linux artifact + Linux host coupling: **proven on hardware**, byte-checked.
- Windows/macOS artifacts + coupling: **proven to the CPU boundary** under
  Unicorn (real entry points, real loader structures emulated, independent
  readers agreeing). Remaining risk is in the native kernel/loader contract,
  not in the code paths exercised.
- The `research/pe/` toolchain is self-contained: `selftest.py` is green on a
  fresh checkout with only the stdlib (+capstone for `disasm.py`).
